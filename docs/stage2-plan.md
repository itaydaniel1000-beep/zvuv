# שלב 2 (תוכנית): המוח המלא של Shiu et al. 2024 מחובר לאתר

המטרה: במקום 16 העיגולים, להריץ על המחשב את המודל המלא (כ-139 אלף נוירונים וכ-15 מיליון חיבורים), ושהאתר ישלח אליו את החיישנים ויקבל ממנו פקודות תנועה.

## 1. המודל עצמו
- הקוד: https://github.com/philshiu/Drosophila_brain_model (הקבצים `model.py`, `Connectivity_783.parquet`, `Completeness_783.csv`, כבר משמשים את `data/build_brain.py`).
- מודל leaky integrate-and-fire ב-Brian2. כל סינפסה מוסיפה משקל קבוע כפול מספר הסינפסות, עם סימן לפי הנוירוטרנסמיטר. הקלט ניתן כירי Poisson בקצב קבוע לנוירונים נבחרים.
- התקנה: `conda env create -f environment.yml` (פייתון, Brian2, pandas, pyarrow).
- בדיקה ראשונה: להריץ את `example.ipynb` ולשחזר תוצאה מהמאמר (למשל: הפעלת נוירוני טעם סוכר מפעילה את MN9, מנוע ההושטה של החדק). כך יודעים שההתקנה תקינה לפני שמחברים משהו.

## 2. הבעיה המרכזית: מהירות
- Brian2 במצב הרגיל מריץ שנייה של סימולציה בזמן ארוך בהרבה משנייה על מעבד רגיל. זבוב שמגיב באיחור של דקות לא יעבוד כבקר בזמן אמת.
- אפשרויות, מהקלה לקשה:
  1. **Brian2 standalone (C++)**: `set_device('cpp_standalone')`. מהיר בהרבה, אבל בנוי לריצה אחת ארוכה ולא ללולאה של "קלט, צעד, פלט". צריך לבנות את הרשת פעם אחת ולהריץ צעדים קצרים (50–100 ms) עם עדכון קצבי ה-Poisson ביניהם.
  2. **GPU**: Brian2CUDA או Brian2GeNN, על כרטיס NVIDIA. זו הדרך הסבירה להתקרב לזמן אמת.
  3. **גרסה מוקטנת**: להשאיר רק נוירונים שנמצאים עד 3–4 סינפסות מהחיישנים שלנו או מה-DNs שלנו (אלפים בודדים במקום 139 אלף). מהיר מאוד, ועדיין "חתיכה אמיתית" של המוח.
  4. **איטי אבל פשוט**: לא בזמן אמת. האתר עוצר את הזירה בזמן שהמוח חושב (מצב "צעד אחר צעד"), כמו סימולציה מדעית.
- הצעד הראשון בפועל: למדוד כמה זמן לוקח צעד של 100 ms על המחשב שלך בכל אחת מהאפשרויות, ורק אז לבחור.

## 3. מה עובר בין האתר למוח
האתר כבר מחשב את החיישנים הווירטואליים (`senseWorld()` מחזיר `eyeL, eyeR, antL, antR, loom` בין 0 ל-1), וכבר יודע לדבר WebSocket עם הרובוט.

מהאתר לשרת, 10–20 פעמים בשנייה:
```json
{ "t": "sense", "eyeL": 0.1, "eyeR": 0.4, "antL": 0.7, "antR": 0.5, "loom": 0 }
```
השרת מתרגם כל ערך לקצב Poisson (למשל 0 עד 150 Hz) לנוירונים של אותה קבוצה, בדיוק לפי ההגדרות ב-`GROUPS` שב-`data/build_brain.py` (פוטורצפטורים לפי צד, ORN לפי אנטנה, LPLC2/LC4).

מהשרת לאתר, אחרי כל צעד:
```json
{ "t": "brain", "rates": { "dnL": 12.0, "dnR": 3.5, "dnF": 20.1, "gf": 0 }, "top": [["DNa02_L", 40.2], ...], "simMs": 100, "wallMs": 380 }
```
`rates` הם קצבי הירי הממוצעים (Hz) של קבוצות ה-DN. האתר ממיר אותם ל-`yaw`, `fwd` ו-`gf` באותו מקום שבו היום `brainStep()` מחזיר אותם, כך ששאר הקוד (פיזיקה, רפלקס בריחה, שליחה לרובוט) לא משתנה. `top` מאפשר להדליק בתרשים המוח את הנוירונים הכי פעילים.

## 4. השרת
- קובץ אחד, `brain_server/server.py`: ספריית `websockets` (asyncio), מאזין על `ws://localhost:8765`.
- בהפעלה: טוען את הנתונים, בונה את הרשת פעם אחת, מחשב את רשימות האינדקסים של כל קבוצה.
- לולאה: לקבל את החיישנים האחרונים, לעדכן קצבים, להריץ צעד, לספור ספייקים לפי קבוצה, לשלוח. אם הגיעו כמה הודעות חיישנים באמצע צעד, משתמשים רק באחרונה.

## 5. שינויים באתר
- מתג שלישי בכרטיס המוח: "מוח מקומי / מוח מלא (שרת)", עם שדה כתובת (ברירת מחדל `ws://localhost:8765`).
- כשהשרת מחובר, `brainStep()` מחזיר את הערכים מהשרת, והעיגולים בתרשים מציגים את קצבי הירי האמיתיים. אם החיבור נופל, חוזרים אוטומטית למודל המקומי.
- הערה: האתר ב-GitHub Pages רץ ב-HTTPS. דפדפנים מאפשרים לדף HTTPS להתחבר ל-`ws://localhost`, אבל לא לכתובת אחרת ב-`ws://`. מחשב אחר ברשת ידרוש `wss://` עם תעודה, או פתיחה של `index.html` מקומית.

## 6. סדר עבודה מוצע
1. התקנה ושחזור תוצאה מהמאמר.
2. מדידת מהירות, ובחירה בין standalone, GPU או רשת מוקטנת.
3. שרת עם קלט קבוע (בלי אתר) שמדפיס את קצבי ה-DN כשמדליקים ריח משמאל או מימין. כאן נבדק אם המודל המלא בכלל פונה לכיוון הריח.
4. חיבור לאתר.
5. כיול: איך הופכים הפרש קצבים בין DNa02 שמאל וימין לסיבוב, ואיזה קצב של Giant Fiber נחשב "ירייה".

סיכון שכדאי לדעת מראש: המודל של Shiu et al. נבדק בעיקר על מעגלי טעם והזנה. אין הבטחה שחיפוש ריח או משיכה לאור יופיעו בו מעצמם. הרפלקס מ-LPLC2 ל-Giant Fiber הוא המועמד הטוב ביותר לעבוד מההתחלה, כי הוא קצר וישיר (כחמישית מהקלט של Giant Fiber מגיע מ-LPLC2/LC4).
